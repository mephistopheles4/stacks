# One `.env` in the main checkout, read by every worktree — never copied

`envFilePath` falls back to `git rev-parse --git-common-dir`, the one `.git` every linked worktree shares. Editing that file changes every worktree at once, which is the point.

A copy drifts with nothing going red: repoint the vault in the main checkout and the worktree keeps building against a path that no longer exists. `STACKS_DEV_HOST=1` is the case that decides it — the only setting here with a consequence outside the machine, and one left behind in three stale copies keeps the shelf on the network long after anyone remembers enabling it.

## How this was decided

*Carried verbatim from the Decision Log this repository kept from July 2026, newest last.*

- **2026-08-01** — **`STACKS_DEV_HOST=1` puts `pnpm dev:watch` on the network, opt-in.** Two of this project's bugs — the crash and the lost context — appeared only on a phone, and there is no other way to see local changes on one without deploying. Off by default because it is the only setting here with a consequence outside the machine: while it is on, anything on the same Wi-Fi can open the shelf and read what you read. The dev build is the same `--public` one the site ships, so `private:` and wishlist books stay off it either way. Read from `.env` as well as the environment, because a variable documented in `.env.example` that only works when exported from a shell is a setting that appears to exist and does not.

- **2026-08-01** — **One `.env`, in the main checkout, read from every worktree — never copied.** A worktree is a real checkout with its own working directory, and both of the things a command here needs are gitignored: `node_modules`, which fails loudly, and `.env`, which fails as `no vault: pass --vault <path>` on a branch where nothing is wrong. Copying `.env` was the obvious fix and is the wrong one, because a copy drifts with nothing going red: repoint the vault in the main checkout and the worktree keeps building against a path that no longer exists. `STACKS_DEV_HOST=1` is the case that decides it — turned on for an afternoon and forgotten in three stale copies, it keeps the shelf on the network long after anyone remembers enabling it, and that is the only setting here with a consequence outside this machine. So `envFilePath` falls back to `git rev-parse --git-common-dir`, the one `.git` every linked worktree shares. The subprocess is only spawned when there is no `.env` beside you, so the main checkout never pays for it.

- **2026-08-01** — **`--git-common-dir` answers relative in the main checkout and absolute in a worktree**, so its parent means nothing until it is resolved. Checked from all three positions rather than assumed — root (`.git`), a subdirectory (`../../.git`), and a linked worktree (absolute) — and pinned by `packages/cli/src/env.test.ts`, which creates a real detached worktree instead of a directory that resembles one. Observed red by deleting the `resolve()`: the three cases return `.`, `../..`, and a forward-slashed path that is a different string from anything `node:path` produces on Windows. That last one is why `resolve()` stays even though the worktree case is already absolute.

- **2026-08-01** — **`dev-watch.ts` stopped carrying its own `.env` reader, and that fixed a documented setting that never worked.** It parsed one key at a time out of `join(ROOT, '.env')` — but `PORT`, which `.env.example` documents, was read from `process.env` alone and never from the file. So setting it in `.env` did nothing: the exact "variable documented in `.env.example` that only works when exported from a shell" that the script's own comment warned about, in the script that carried the warning. One loader now, the CLI's, which also gets the worktree fallback for free.

- **2026-08-01** — **Worktrees go beside the main checkout, not inside it.** Nested would in fact be safe — `filesUnder` skips dot-prefixed directories and the tsconfig and vitest globs are anchored at `packages/`, `scripts/` and `gates/`, which is why `.claude/worktrees/` can sit where it does — but that is three independent coincidences, and neither Astro's file watcher nor an editor's indexer shares any of them. Written down because the next agent to "tidy up" the dot-directory skip will not otherwise know what it was holding up.

- **2026-08-01** — **`smoke:render` asks the OS for a port instead of insisting on 4331.** Fine while one checkout existed; with worktrees, two gates racing is normal, and a fixed port has two failure modes. `EADDRINUSE` is the good one — a gate that fails for a reason unconnected to the shelf. The bad one is a server from another checkout still up and serving *its* `dist/`, so the gate screenshots another branch's shelf, scores it, and reports the number as this branch's. Both were reachable, and a stray server outliving its session on a fixed port has already happened here. Nothing outside the script needs the number, so nothing outside the script has to agree on one. `URL` went with it, which also stops a module-scope binding shadowing the global `URL` constructor.

- **2026-07-31** — Vault path comes from `--vault` or `STACKS_VAULT`; there is no config file. `--out` defaults to `library.json` in the cwd.
