# The decision record is ADRs, extracted from a chronological log

Decisions live here, in `docs/adr/`, one file per decision. They were extracted from a 138-entry chronological Decision Log that had grown to 85% of CLAUDE.md by weight.

The log's other genres went where they already belonged: gate observations to [`docs/gates.md`](../gates.md), environment findings to [`docs/progress.md`](../progress.md). Entries are carried verbatim under each decision rather than paraphrased, because the reasoning is the value and several of these were expensive to learn.

## How this was decided

*Carried verbatim from the Decision Log this repository kept from July 2026, newest last.*

- **2026-08-02** — **The Decision Log moved to `docs/decisions.md`, unchanged, because it was 85% of CLAUDE.md by weight.** Measured before deciding: the operative part of that file — invariants, contracts, commands, working rules, the things an agent must actually obey — was 187 lines and 2,261 words; the log was 152 lines and 12,977 across 132 entries. So the rules were outnumbered five to one in their own file by the record of decisions *about* them. Nothing parses the log, which is why it could move at all; `gates/commands.test.ts` and `gates/frontmatter-contract.test.ts` both **throw** on a missing `## Commands` or `## Frontmatter contract` heading, so those two stay where they are permanently. Not one entry was edited — the file is byte-identical below its new header.

- **2026-08-02** — **Not ADRs, and that is the decision rather than an omission.** One file per decision is the obvious destination and the wrong one here. Several of these entries are only legible in sequence: the shadow-map investigation is six of them ending in *"sizing an allocation predicted the wrong answer"*, and the correction is the valuable half of the chain. ADRs are one-decision-per-file precisely because an ADR is not a narrative, and this is. So `docs/adr/` stays available for a genuinely standalone architectural choice — one a reader could evaluate without the log above it — and `docs/agents/domain.md` says which is which. A new ADR gets a pointer line from here, so one place still lists everything in order.

- **2026-08-02** — **The engineering skills are configured, and configured as optional.** `docs/agents/` records the issue tracker, the triage labels and the domain-doc layout that `mattpocock/skills` reads. Single-context, though the repo trips every monorepo signal — `core`, `cli` and `site` are layers of one domain sharing one vocabulary, not bounded contexts, and a `CONTEXT-MAP.md` over three packages that all mean the same thing by *book* is ceremony. The load-bearing rule is written into CLAUDE.md, CONTRIBUTING.md and the files themselves: **nothing in this repo's workflow may require them.** Nothing under `docs/agents/` is read by a gate, a script or CI, and a contributor with none of them installed must pass every gate. A workflow that only works on the owner's machine is the same defect class this project keeps gating against — a documented claim nobody else can check.

- **2026-08-02** — **The README gets a screenshot, and G13 gets narrower rather than wider to allow it.** A picture is the one thing a reading-tracker README cannot do without, and `artifacts/` is gitignored precisely because screenshots are regenerable — so the image had to become a tracked binary, which G13 forbids outside an allowlist. The safe source already existed: `pnpm smoke:render` renders the **50-book fixture vault**, where every title is invented, so `scripts/make-readme-image.ts` crops that. The risk is not the file, it is the *directory* entry: unlike every other line in that allowlist it is a standing permission, and no test can look at a PNG and tell an invented shelf from a real one. So `docs/images/` is pinned to exactly `shelf.png` — a second picture goes red, replacing this one stays a reviewable diff. Weaker than the covers row, and recorded as weaker.

- **2026-08-02** — **`sharp` added to the root devDependencies, for the crop.** It has been a `packages/core` dependency since Phase 1 and is already in the lockfile; pnpm's strict layout just will not resolve it from a root-level script. The alternative was a hand-rolled PNG decoder over `node:zlib` — the repo has a ~40-line *encoder* for the fixture covers, so it is not unthinkable — and it is the same trade this project already refused when it declined to hand-roll a YAML parser. Third use for a library chosen twice over.

- **2026-08-02** — **Reversed on the same day, and the entry above is left standing because the correction is the point.** "Not ADRs" rested on the claim that these entries are only legible in sequence. Measured rather than asserted, that is **15 of 138 with an explicit back-reference — 11%**, and two saying "superseded". The narrative problem is real and confined; it did not characterise the file, and it was presented as though it did. What actually holds is `ADR-FORMAT.md`'s own rule — *offer ADRs sparingly*, all three of hard-to-reverse, surprising-without-context, real-trade-off — under which most entries are not decisions at all but findings, bug post-mortems and gate observations. Migrating all 138 would have put ~120 non-ADRs in `docs/adr/` and buried the ones that matter. So: 25 records, each carrying its own entries verbatim; nine gate lessons to [`docs/gates.md`](../gates.md); one duplicate of an environment finding already in `progress.md` dropped. The unit is one *decision*, not one entry — which is why the shadow investigation is a single record holding twenty-five.
